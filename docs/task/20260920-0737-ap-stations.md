## Description

Device testing asked to see the clients connected to the device's own WiFi.
The console showed Wi-Fi *associations* -- this device joining someone else's
network -- and had nothing for the other direction, because micad observed
nothing for it.

It could not have: the rendered hostapd configuration carried no
`ctrl_interface=`, so hostapd opened no control socket and there was nowhere
to ask.

## What changed

- The AP reconciler renders `ctrl_interface=/run/hostapd`. Under `/run`, so
  it is a runtime path on a read-only root and goes with the boot that made it.
- `network_state.rs` walks the stations over that socket with the same client
  wpa_supplicant is asked through -- hostapd speaks the same protocol --
  bounded at 64 stations, because the walk is one round trip per station inside
  an observation somebody is waiting on.
- The observation gains `accessPoint`: per interface, the station count and
  each station's address, signal, connected time and byte counters. **No
  credential**: hostapd's reply carries key negotiation state and none of it is
  read.
- An interface with no hostapd on it is reported as one rather than as an
  access point with no clients, and a device running none reports the member
  absent rather than empty.
- The console's observed tab shows them beside the associations, named apart:
  one is this device joining a network, the other is a network joining this
  device.
